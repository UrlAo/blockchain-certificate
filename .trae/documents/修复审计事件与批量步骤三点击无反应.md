## 问题诊断
- 他人拉取后直接用浏览器打开 `file://`，`fetch('abi.json')` 与 `crypto.subtle.digest` 常在非安全上下文失败，导致 `init()`/计算哈希抛错，按钮点击无响应。
- 审计页强制切换到本地链 `0x7A69`，他人未运行本地 RPC（`http://127.0.0.1:8545`）时，`getNetwork()`/合约实例创建失败，事件加载按钮不启用。
- 批量页的“生成并验证证明”未确保 `contract` 已初始化，且未对 `verifyLeaf` 的调用做错误捕获；按钮启用逻辑未包含 `contract`，出现“可点但无结果”。

## 改动方案（前端）
### 审计页 `frontend/audit.html`
1. 放宽网络要求：移除强制 `wallet_switchEthereumChain`/`wallet_addEthereumChain`，直接连接当前钱包网络；若非目标网络，在 UI 显示提示而不是阻断。
2. 增强初始化健壮性：
   - `fetch(CONFIG.ABI_URL)` 加 `try/catch`，失败时在 `summary` 显示“无法加载 ABI（请通过 HTTP 服务运行并确保 `abi.json` 存在）”。
   - `provider.getNetwork()`/合约实例化加 `try/catch`，失败时禁用导出按钮并给出错误详情。
3. 事件加载容错：`loadEvents()` 包装整体 `try/catch`；当合约/Provider不可用时，展示明显错误卡片，而非静默失败。
4. 代码位置：`init()` 与 `loadEvents()` 均有修改（参考 `frontend/audit.html:38–62`, `64–112`, `56–58`）。

### 批量页 `frontend/batch.html`
1. 初始化保障：在 `genAndVerifyProof()` 首行增加 `if (!contract) await init()`，确保只读调用有合约实例（`frontend/batch.html:146–159`）。
2. 按钮启用逻辑修正：`canProof = Boolean(root) && Boolean(contract) && pf.files.length > 0`，避免未初始化即允许点击（`frontend/batch.html:168–179`）。
3. 安全上下文提示：
   - `computeSha256()` 包 `try/catch`，遇到 “The operation is not secure” 时在 `proofBox`/弹框明确提醒“请通过本地 HTTP 服务器或 https 打开页面”。
4. 只读校验容错：`genAndVerifyProof()` 包装 `contract.verifyLeaf` 的 `try/catch`，在失败时输出错误信息而不是无响应。
5. 代码位置：`init()`, `computeSha256()`, `genAndVerifyProof()`, `updateButtons()`（参考 `frontend/batch.html:54–67`, `69–75`, `146–159`, `161–179`）。

### 配置与可移植性
- 在 `frontend/config.js` 保留 `CONTRACT_ADDRESS`/`ABI_URL`，后续可新增可选 `REQUIRED_CHAIN_ID`（若提供则给出 UI 提示而不强制切链）。
- 文档化运行方式：他人需通过本地 HTTP 服务打开 `frontend`（例如 `python -m http.server` 或任意静态服务器），并确保钱包连接到已部署合约的网络与地址。
